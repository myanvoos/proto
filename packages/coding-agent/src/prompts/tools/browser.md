Drives real Chromium tabs; full puppeteer access via JS. Static content → `read` the URL; browser only for JS execution, auth, interactive actions. `action` is ONLY `open` | `close` | `run` — screenshots (`tab.screenshot()` inside `code`), clicks, and fills happen inside `run`; there is no selector/screenshot action parameter.

- MUST `open` before `run`; tabs survive calls and subagents — open once, reuse.
- `run` scope: `page`, `browser`, `tab`, `display`, `assert`, `wait`; `wait(fn)` polls until truthy — never poll inside `tab.evaluate`. `code` runs with full Node access — not sandboxed. `tab` mirrors puppeteer; drop to raw `page` for anything uncovered.
- `page.evaluate` defaults to an isolated `window`. App/preload globals → use a leading callback directive: `await page.evaluate(() => { /*!world=main*/ return window.__sentinel; })`.
- Handles: `tab.ref("e5")`/`tab.id(n)` → call methods directly — `(await tab.id(n)).click()`. Handles are NOT selectors; string-selector helpers take selectors only. Snapshot refs work in any selector slot: `tab.click("e5")` ≡ `tab.click("aria-ref=e5")`.
- Default `tab.observe()` → accessibility tree; `ariaSnapshot()` → ARIA YAML with `[ref=eN]`; screenshot only for appearance. `tab.screenshot({ selector?, fullPage?, silent? })` saves to `browser.screenshotDir` (else OS temp), returns path; NEVER accepts a path.
- Gotchas: `tab.fill` NEVER works for `<select>` — use `tab.select`. `waitForNavigation` must start BEFORE the trigger click. Navigation/re-renders invalidate ids/refs — re-observe, act in same cell. Request interception is run-scoped: run end removes handlers, releases held requests. After clicks/navigation, SHOULD use `tab.waitFor`, `waitForSelector`, or `waitForUrl` for the expected state instead of fixed sleeps.
- Action helpers accept an optional trailing `{ timeout }` options object; `timeout` is milliseconds and is capped by the current browser run.
- Omitted `app` → configured relay (the user's own signed-in Chrome; `PI_BROWSER_RELAY=1` forces on, `=0` off), then `browser.cdpUrl`, cmux, managed Chromium. `app.relay: false` skips relay even when enabled by environment; configured CDP/cmux still precede Chromium.
- `app.path` → NEVER tamper with a real desktop app. `app.relay: true` → the user's signed-in Chrome via the relay extension. `app.target` borrows an existing tab: exact target id first, then URL/title substring. Without a target, relay/fresh Chromium opens a tool-owned background tab; other CDP apps borrow a usable page. Screenshots NEVER select another tab.
- `close` releases the session; `all: true` releases only this live session's tabs. Tool-owned pages (including relay/fresh Chromium tabs) and cmux surfaces close; borrowed pages stay open. `kill: true` may also terminate a spawned app, NEVER the user's connected/relay browser.
- Selectors: CSS + `aria/…`, `text/…`, `xpath/…`, `pierce/…`; Playwright-only pseudos (`:has-text()`, `:visible`) REJECTED.
